# Demo vs Real

**Mandatory transparency document (MISSION §34).** Anyone evaluating this prototype must be able to
tell, without reading code, which parts are real engineering and which are simulated. Nothing below
is softened: where a number is invented, it says so.

Classification used throughout:

| Label | Meaning |
|---|---|
| **Real implementation** | Actual working code that computes the result from inputs |
| **Local simulation** | A real simulator producing genuine results — but of a model, not hardware |
| **Heuristic** | A defensible formula with documented assumptions; not measured, not fitted to hardware |
| **Static demo data** | Seeded fixtures, deterministic across reloads |
| **Planned integration** | Declared interface only. Not implemented, never faked |

---

## Quantum error correction

| Feature | Classification | Notes |
|---|---|---|
| Repetition + rotated surface code simulation | **Local simulation** | Real **Stim** circuits, real **PyMatching** MWPM decoding. Genuine Monte-Carlo results of a noise *model* — not a physical device. |
| Threshold grid (`demo-data/qec/threshold_grid.json`) | **Local simulation**, shipped as **static demo data** | 216 rows generated by `scripts/generate_qec_fixtures.py` through the same service the API uses. Seeded; regenerating reproduces it on the pinned versions/platform. |
| Logical error rates, Wilson CIs, per-round normalisation | **Real implementation** | Computed from the simulated shot counts. `insufficient_statistics` is flagged rather than hidden. |
| Decoders other than MWPM (BP, BP-OSD, Union-Find, GPU) | **Planned integration** | Declared in the decoder registry with `NOT_IMPLEMENTED` and **null on every metric**. No fabricated benchmarks. |
| Threshold *value* | **Not claimed** | We plot the crossing region; we never print a single threshold number from three distances. |

## Quantum error mitigation

| Feature | Classification | Notes |
|---|---|---|
| Technique compatibility matrix | **Real implementation** | `docs/data/qem_compatibility.json` is the single source; the engine interprets it — no rule is re-encoded in Python. |
| Bias / variance model (`rmse = √(bias² + std²)`) | **Heuristic** | Global-depolarising approximation with a 4-channel error budget. Assumptions are written down in `QEM_METHODS.md` and are meant to be attacked. |
| Sampling overhead (ZNE amplification, PEC γ²) | **Heuristic** | Closed-form from the documented technique parameters. |
| Executed mitigation on real circuits | **Not implemented** | The platform *plans and prices* mitigation; it does not execute Qiskit/Mitiq pipelines in V1. |
| PEC | **Heuristic (calculator only)** | Ships as a feasibility/overhead calculator. Never offered as a runnable strategy (RECON-13). |

## Optimizer & preflight

| Feature | Classification | Notes |
|---|---|---|
| Two-stage optimizer (hard pre-filter → weighted score) | **Real implementation** | Constraints are a gate, not a weight: a violated cap can never be out-scored. |
| Score normalisation ranges | **Real implementation** | Fixed and documented — never per-batch min-max, so scores compare across runs. |
| Preflight status + reason codes | **Real implementation** | Status is *computed* from findings by a shared precedence rule, never hand-set. |
| Explanations | **Real implementation** | Template-generated from the structured breakdown. No LLM prose in the product. |

## Hardware & calibration

| Feature | Classification | Notes |
|---|---|---|
| Demo backends (Hex-Lattice 27, Square-Grid 16, Ring 12) | **Static demo data** | Synthetic devices. Named "Demo …" precisely so they are never mistaken for real machines. |
| Calibration history & drift | **Static demo data** | Deterministic 14-point series from a seeded drift factor. |
| Unavailable fields (e.g. quantum volume) | **Honest null** | Rendered "Not provided" — never zero (§20). |
| IBM / IQM / Rigetti / IonQ / Quantinuum adapters | **Planned integration** | Interface declared, `adapter_status: adapter_planned`. No credentials, no calls, no claimed partnership. |

## Cost & time

| Feature | Classification | Notes |
|---|---|---|
| Cost and QPU-time estimates | **Heuristic** | Config-based price × modelled seconds. No live pricing is scraped. Every figure is labelled *estimated*. |
| "Actual" runtime / cost on receipts | **Always null in demo** | Enforced by invariant: `execution_mode == "demo_replay"` ⇒ `actual_*` is null. A demo receipt *cannot* syntactically claim a measured runtime. |

## The web prototype

| Feature | Classification | Notes |
|---|---|---|
| Everything on the GitHub Pages site | **Static demo data + in-browser computation** | No server, no account, no telemetry. The optimizer/preflight run client-side from seeded fixtures. |
| "Reliability Health", "Goal pass rate" | **Heuristic**, labelled illustrative | Composite scores always expose their formula and weights (ExplainedScore). |
| Backend REST API | **Real implementation**, local only | Runs the same engines; not deployed publicly (Pages is static by design, §48). |

---

## What would make this real

1. Implement a provider adapter (e.g. IBM) behind the existing interface — server-side only, credentials never in the browser.
2. Execute the planned strategy and record **measured** results, flipping `execution_mode` to `hardware` so `actual_*` fields populate.
3. Replace heuristic bias estimates with values learned from the accumulated experiment history (the data model already preserves what that needs).

Until step 2 exists for a given run, every reliability number in this product is a **model**, not a measurement — and the UI says so.
